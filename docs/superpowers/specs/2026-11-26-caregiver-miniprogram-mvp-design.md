# 护理员端微信小程序 MVP 设计

日期：2026-11-26

## 决定

口述护这一期只做护理员端原生微信小程序。Android 和 iOS 都通过微信使用，不做独立 App，也不把现有 Vue H5 嵌进 web-view。现有 `frontend/` 联调页保留，不作为本期交付界面。

产品路径按需求书 V1.1：微信登录、阿里云 OSS 保存原声和影像、DashScope `paraformer-realtime-v2` 做 16k PCM 流式识别。后端继续用现有 Spring Cloud（网关、语音服务、护理服务），不新增微服务。

## 范围

本期做：

- 微信登录，并绑定到已有人员。一个微信号只绑定一个人员。
- 班次模板和按日排班。默认白班 08:00–20:00，夜班 20:00–次日 08:00。
- 在住老人床号、姓名、口语别名。
- 按住说话、流式出字、松开后立刻保存原声、结构化预览、确认。
- 异常记录可拍照或录不超过 15 秒的短视频。
- 本班交接清单四段生成、补充语音或影像、确认交班后锁定。
- 班结束前 30 分钟的订阅消息。未授权时只在首页提示。

本期不做：

- 接班确认页面和接班操作。首页「确认」按钮固定不可用，文案为「接班确认下一期开放」。
- 院长端页面：今日异常、记录查询、导出、确认率、基础设置。
- 家属端。
- 独立 Android 或 iOS 安装包。
- 用 mock 文本冒充真实识别结果。

院长和护理主管在本期只通过基础数据接口维护人员绑定、老人和排班。他们登录小程序时看到「院长端下一期开放」，不进入护理员首页。一个微信号不能同时是护理员和院长。

## 架构

```text
微信小程序
  wx.login  code  →  网关 /api/auth/wechat  →  护理服务
  按住说话 PCM 帧  →  网关 /ws/asr          →  语音服务 → DashScope
  松开后的整段原声  →  网关 /api/nursing     →  护理服务 → 阿里云 OSS
  预览、确认、交接  →  网关 /api/nursing     →  护理服务 → MySQL
```

小程序只访问网关。请求合法域名和 socket 合法域名都指向网关。WebSocket 使用 `Authorization` 头携带会话。

部署环境的护理服务使用 MySQL。原声和影像的对象键存在 MySQL，文件在 OSS。播放使用 10 分钟有效的签名 URL，小程序不保存 OSS 永久地址。

密钥由运行环境提供，不写入仓库：

- `WECHAT_APPID`
- `WECHAT_SECRET`
- `WECHAT_SUBSCRIBE_TEMPLATE_ID`
- `DASHSCOPE_API_KEY`
- `OSS_ENDPOINT`
- `OSS_BUCKET`
- `OSS_ACCESS_KEY_ID`
- `OSS_ACCESS_KEY_SECRET`

没有 `DASHSCOPE_API_KEY` 时，真实录音链路直接失败并说明缺密钥。自动化测试不读取这些密钥。

## 页面与流程

小程序页面只有：未绑定或停用说明、未排班说明、护理员首页、录音、预览、记录详情、本班交接。

首页在已绑定、已启用、且当天有排班时显示「你好，{姓名}」、当前班次和时段、负责老人数、已确认条数。三个大按钮保留：记录（绿）、交接（蓝）、确认（橙）。正文不小于 18px，姓名和主按钮标题不小于 22px。没有图表和其他入口。

记录流程：

1. 可先选在住老人，也可以直接说「几床谁」。
2. 按住录音。最短 1 秒，最长 60 秒。未满 1 秒松开不建记录。满 60 秒自动停止并进入预览。
3. 按住期间，16kHz、16-bit、单声道 PCM 帧只发给 `/ws/asr`。屏幕在松手之前就要出现部分文字。
4. 松开后，把本次完整原声立刻上传 OSS，不等用户点确认。
5. 预览页展示可修改的原文、原声播放条、结构化字段。异常字段标橙。异常记录可以拍照或录不超过 15 秒的短视频。
6. 床号和姓名必须匹配在住名册，或由护理员手选老人。未确定老人不能确认保存。
7. 确认保存后，原文、原声、结构化结果和影像进入该老人时间线，并记下确认时刻（精确到分钟）和记录人。记录归入该时刻所在班次。

原声与文本分开存放。预览页可以改文本。确认后的原文、原声和影像不能删除、不能覆盖。重录只丢弃尚未确认的预览及其原声。说错了再录一条更正，新记录指向原记录，并关联同一老人。

交接流程：

1. 护理员可随时打开交接页。系统用本班已确认记录生成四段：整体情况、重点关注、遗留事项、物资设备。
2. 整体情况包含负责人数、平稳人数、需重点关注人数，不能只写「一切正常」。
3. 重点关注只收记录类型为异常的已确认记录。遗留事项只收记录类型为遗留的已确认记录，包括家属交代。物资设备只收记录类型为物资的已确认记录；本班没有物资记录时，该段显示「本班未口述物资情况，请补充或确认无异常」。
4. 条目可以补一句语音、一张照片或一段不超过 15 秒的短视频。不能删除系统已归集的原文和原声。
5. 没有照片不阻止交班，只提示「可补拍现场」。
6. 确认交班后，清单、原声引用和已附影像锁定，记录交班人和时间。漏项必须新录一条护理记录，再重新生成尚未提交的清单。已提交清单不能靠重新生成修改。

班次结束前 30 分钟发送一条订阅消息，正文为班次名称和「距下班还有 30 分钟，请完成交接」。`WECHAT_SUBSCRIBE_TEMPLATE_ID` 为空或用户没授权时，不发送，只在首页显示同一句提醒。

## 数据与接口

在现有表上扩展，不另起一套记录模型。

- 人员：增加唯一的微信 openId、启用标记。角色为 `caregiver`、`head_nurse`、`admin`。
- 老人：沿用床号、姓名、口语别名、性别、在住状态。匹配只用在住老人。退住后不再进入匹配列表，历史记录仍保留。
- 班次模板：名称、开始时间、结束时间。跨日夜班的结束时间落在次日。
- 排班：日期、班次模板、人员。本期负责范围固定为全部在住老人。班次边界按 Asia/Shanghai 计算。
- 记录：增加识别状态（流式中、已终稿、失败已留原声）、所属排班、更正所指向的原记录。原声字段保存 OSS 对象键。确认后 `originalAudio` 保持为真，且该对象拒绝覆盖和删除。
- 会话：不透明随机令牌、人员、过期时间。有效期 7 天。
- 交接：沿用现有清单和条目。条目类型为整体情况以外的重点关注、遗留事项、物资设备。整体情况写在清单摘要上。

对象键格式：

- 原声：`originals/{staffId}/{yyyyMMdd}/{uuid}.pcm`
- 影像：`media/{recordOrItemId}/{uuid}.{ext}`

接口：

- `POST /api/auth/wechat`，正文 `{ "code": "..." }`。已绑定且启用时返回会话令牌和角色。未绑定、已停用分别返回固定错误码 `UNBOUND`、`DISABLED`，不发令牌。
- `GET /api/nursing/me/home`。护理员返回班次、人数和按钮状态。院长或主管返回「院长端下一期开放」，不返回护理员数据。
- `GET /api/nursing/meta/elderly` 只返回在住老人，供录音页选择和口述匹配。
- 现有创建记录、确认、媒体和交接接口保留，并改为要求会话。创建记录时带上原声对象键和识别状态。未确定老人时拒绝确认。
- `POST /api/nursing/original-audio` 在松开后立即把整段 PCM 写入 OSS，返回对象键和时长。时长不足 1 秒时拒绝写入，不创建记录。识别是否成功不影响已达 1 秒的原声写入。
- `POST /api/nursing/original-audio/{objectKey}/retry-asr` 对已落盘原声重新送识别。失败时不更换对象键。
- `GET /api/nursing/media/{id}/url` 返回 10 分钟签名 URL。
- 基础数据接口要求角色为 `admin` 或 `head_nurse`：人员绑定 openId、启用或停用、老人新增和退住、班次模板、按日排班。小程序没有这些页面。

`/ws/asr` 在会话有效时接受二进制 PCM 帧，并把部分文字和终稿推回小程序。语音服务在 `yl.asr.provider=dashscope` 时把帧送给 DashScope `paraformer-realtime-v2`。现有 FunASR 和 mock 引擎保留给开发与测试，小程序产品路径不调用它们。

网关把 `/api/auth/**` 转到护理服务。已有的 `/api/nursing/**` 和 `/ws/asr/**` 路由不变。

## 失败行为

- 识别失败、DashScope 报错或 WebSocket 中途断开：已出的部分文字留在屏幕上。原声先留在手机临时文件，再上传 OSS。上传成功后提示「原声已保存，文字识别失败，可重试识别或重录」。上传失败则保留本地文件并允许再传。不得丢弃这段录音。
- 没有 `DASHSCOPE_API_KEY`：录音链路失败并说明缺密钥，不返回假想的识别文本。
- 麦克风未授权：停在录音页，说明要在微信里打开麦克风。
- 会话过期：重新 `wx.login`。小程序不持久保存 openId。
- 床号匹配失败：预览页强制手选老人，未选不能确认保存。
- 确认之后：原文、原声和影像不能删、不能覆盖。
- 交接已提交：清单只读。未提交清单可以在新增确认记录后重新生成。

## 测试

自动化测试不连接微信、DashScope 和 OSS。护理服务测试使用 H2，并关闭 Nacos。对象存储、微信 code 换 openId、DashScope 都用测试替身。语音终稿用现有 mock 引擎，识别失败用一个总会失败的引擎。

接口测试覆盖：

- 已绑定护理员得到首页；未绑定、已停用、未排班不能进入业务。
- 口述匹配在住老人和别名；退住老人不再匹配。
- 常规、异常、遗留、物资记录的字段，以及它们是否进入交接候选。
- 未确定老人不能保存。
- 确认后不能覆盖原声。更正是新记录并指向原记录。
- 识别失败时原声对象仍然存在。
- 60 秒时长可以被接受。短于 1 秒的上传不创建记录。
- 本班四段清单内容正确。提交后只读。
- 物资未口述时，确认无异常后可以提交。
- 08:30 确认的记录归入当日白班。

小程序的按住说话、松手前出字、原声播放，不放入这套自动化。在提供 `WECHAT_APPID`、`WECHAT_SECRET`、`DASHSCOPE_API_KEY` 和 OSS 密钥之后，用手工清单在 Android 微信和 iOS 微信各走一遍：登录、未绑定、录音出字、识别失败仍能听原声、确认、交班锁定。密钥未提供时，这份手工清单不算通过。

## 现有代码怎么接

- 新的小程序放在仓库根目录 `miniprogram/`，使用微信原生页面，不引入 uni-app 或 Taro。
- `DashScopeStreamingAsrEngine` 补上真正的 PCM 推帧。没有密钥时维持失败，不把终稿文本假装成识别结果。
- 护理服务的本地磁盘媒体实现保留为测试替身。产品配置改为 OSS。
- 现有 H5 演示页和 FunASR 路径不删除。
